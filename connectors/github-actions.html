Build with GitHub Actions

Send SMS from your GitHub Actions workflows.

View Alive5 on GitHub Marketplace ↗

Connect your account

  1. Save your API key

    In Alive5, open Integrations → API Key. Copy or generate your API key and save it as the GitHub Actions repository secret ALIVE5_API_KEY.

  2. Find your sender details

    Use channels-and-users/list with your API key. In data.Items, choose the SMS channel whose channel_label matches your business number. Copy its channel_id and an assigned agent’s agents[].user_id. Store the business number, channel ID, and user ID as repository variables ALIVE5_FROM, ALIVE5_CHANNEL_ID, and ALIVE5_USER_ID.

Send an SMS

Configure the action with these required inputs:

InputValue
api-keyYour Alive5 API key, supplied through a GitHub secret.
fromYour Alive5 business SMS number in E.164 format.
channel-idThe SMS channel associated with the sender number.
user-idAn agent assigned to that channel.
toThe recipient in E.164 format, such as +14155550123.
messageNonblank SMS text. Whitespace is preserved.

Example workflow

  1. Save your API key as ALIVE5_API_KEY and your sender details as ALIVE5_FROM, ALIVE5_CHANNEL_ID, and ALIVE5_USER_ID in repository settings.
  2. Save the workflow below in .github/workflows/. Replace the recipient number and message.
  3. Run the workflow manually to send an SMS. The action needs no GITHUB_TOKEN permissions.
  4. Check the Send SMS step result. Read ${{ steps.sms.outputs.message-id }} and ${{ steps.sms.outputs.conversation-id }} in later steps.
YAML
name: Send SMS
on: workflow_dispatch
permissions: {}
jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - name: Send SMS
        id: sms
        uses: imraghavojha/alive5-sms-action@v1
        with:
          api-key: ${{ secrets.ALIVE5_API_KEY }}
          from: ${{ vars.ALIVE5_FROM }}
          channel-id: ${{ vars.ALIVE5_CHANNEL_ID }}
          user-id: ${{ vars.ALIVE5_USER_ID }}
          to: '+14155550123'
          message: 'Your workflow has completed.'

Check the result

Read ${{ steps.sms.outputs.message-id }} and ${{ steps.sms.outputs.conversation-id }} in later steps. The conversation ID is empty if absent. Success confirms submission, not delivery.

Limits

The action runs on Node.js 24. Self-hosted runners need version 2.327.1 or later. The v1 tag follows compatible releases; pin a full commit SHA for strict reproducibility.

HTTP failures and Alive5 response errors fail the step. Requests time out after 20 seconds, with no automatic retries. Check conversation history before retrying an unclear result to avoid duplicate texts.
