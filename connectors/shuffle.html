Build with Shuffle

Send SMS and read recent conversations from your Shuffle workflows.

View Alive5 on Shuffle ↗

Add the app and authenticate

  1. Find Alive5 SMS

    In Shuffle, open Apps and search for Alive5 SMS, or find it under Discover public apps. Add the public app to your workspace.

  2. Connect your account

    In the app authentication, enter your Alive5 API key. The app sends it in the X-A5-APIKEY header with no prefix.

  3. Add an action

    Open a workflow, add Alive5 SMS, and select an action and your saved authentication.

Available actions

Action nameWhat it doesKey inputs and outputs
List channels and users
list_channels_and_users		Find accessible channels and their assigned users.No action inputs. Returns data.Items with channel_id, channel_label, and agents containing user_id and screen_name.
Send SMS
send_sms		Submit one outbound text message.Requires phone_number_from, phone_number_to, channel_id, user_id, and message. Returns data.data.message_id.
List SMS conversations
list_sms_conversations		Read a snapshot of recent SMS conversations.No action inputs. Returns conversations in data.Items.

Send an SMS

  1. Run List channels and users. In data.Items, choose an SMS channel whose channel_label is your business phone number.
  2. Copy its channel_id and an assigned agent's user_id. Use that channel's business number as phone_number_from.
  3. Add Send SMS after the lookup. Map those three values, set phone_number_to to a number you control, and enter a message such as Hello from Alive5. Use E.164 format for both numbers, such as +14155550123.
  4. Run the workflow to send a real SMS. Check the response body for errors, then look for the message ID at data.data.message_id. Confirm the text arrives on your phone.

A message ID confirms submission, not delivery. Before automating sends, use recipients who have agreed to receive texts from your business.

Check responses

Alive5 may return HTTP 200 with an error in the response body. Add a workflow condition after each action and check these fields before continuing:

  • code and data.code: inspect application status codes for a failure.
  • error, data.error, and data.errors: check for error details. An empty error object is used in successful responses.

See API errors and responses for details. If a send result is unclear, inspect conversation history before retrying to avoid duplicate texts.

Limits

  • The app has no automatic inbound-message trigger. Start the workflow with a Shuffle trigger or schedule.
  • List SMS conversations covers recent activity. It is a snapshot, not a complete message archive.
