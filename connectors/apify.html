Build with Apify

Send SMS to one or many recipients from Apify.

View Alive5 on Apify ↗

Connect your account

  1. Get your API key

    In Alive5, open Integrations → API Key. Copy or generate your API key and enter it in the Actor’s secret Alive5 API key field.

  2. Find your sender details

    Use channels-and-users/list with your API key. In data.Items, choose the SMS channel whose channel_label matches your business number. Copy its channel_id and an assigned agent’s agents[].user_id. Enter the business number, channel ID, and assigned user ID in the Actor.

Send an SMS

Open the Alive5 SMS Sender Actor, fill in all six required fields, and run it. Each recipient receives a separate SMS submission.

InputValue
apiKeyYour Alive5 API key. Apify encrypts this secret input on the platform.
fromYour Alive5 business SMS number in E.164 format.
channelIdThe SMS channel associated with the sender number.
userIdAn agent assigned to that channel.
toAn array of unique E.164 recipient numbers, even for one recipient.
messageNonblank SMS text sent unchanged to every recipient.

Example run

  1. Open the Alive5 SMS Sender Actor and enter your API key, business SMS number, channel ID, and assigned user ID.
  2. Add a recipient in E.164 format to to and enter your message. For JSON input, replace the example credentials and numbers below.
  3. Run the Actor to submit a separate SMS for each recipient.
  4. Open Output → SMS submission results and check every recipient’s status, messageId, and error.
JSON
{
  "apiKey": "YOUR_ALIVE5_API_KEY",
  "from": "+14155550100",
  "to": ["+14155550123"],
  "message": "Your requested update is ready.",
  "channelId": "YOUR_SMS_CHANNEL_ID",
  "userId": "YOUR_ASSIGNED_USER_ID"
}

Check the results

Open Output → SMS submission results. The dataset contains one record per recipient, in input order. Export it as JSON or CSV, or retrieve it through the Apify API.

FieldValue
toThe recipient number.
statusaccepted or failed. Acceptance confirms submission, not delivery.
messageIdThe submitted message ID, or null on failure.
conversationIdThe conversation ID, or null if absent or failed.
errorA redacted error string on failure, otherwise null.

A run succeeds if at least one submission is accepted. Check every record for individual failures. If none are accepted, the run fails after saving the results.

Limits

Requests run sequentially, time out after 20 seconds each, and are not retried automatically. Check Alive5 conversation history before retrying an unclear result. Rerunning or scheduling the Actor submits messages again; it does not deduplicate across runs.

Alive5 SMS charges and Apify platform or Actor charges apply separately.
