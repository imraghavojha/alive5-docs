Build with Directus

Send SMS from your Directus Flows.

View Alive5 on Directus ↗

Install

In Directus, open Settings → Marketplace, search for Alive5 SMS, and verify the package scope @imraghavojha. Or install @imraghavojha/directus-extension-alive5-sms from npm. The extension supports Directus 10.10 and later 10.x releases, and Directus 11.x.

For a self-hosted instance, copy the package’s package.json and dist directory into extensions/directus-extension-alive5-sms, then restart Directus.

Connect your account

  1. Get your API key

    In Alive5, open Integrations → API Key. Copy or generate your API key.

  2. Find your sender details

    Use channels-and-users/list with your API key. In data.Items, choose the SMS channel whose channel_label matches your business number. Copy its channel_id and an assigned agent’s agents[].user_id. The sender and channel must be enabled for SMS.

Send an SMS

Create a Flow, add Send SMS (Alive5), and give it the operation key send_sms. All six options are required:

OptionValue
API key / apiKeyYour Alive5 API key or {{$env.ALIVE5_API_KEY}}.
Channel ID / channelIdThe SMS channel associated with the sender number.
User ID / userIdAn agent assigned to that channel.
From number / fromYour Alive5 business SMS number in E.164 format.
To number / toAn E.164 recipient number or a Flow expression such as {{$trigger.payload.phone}}.
Message / messageNonblank SMS text, optionally including Flow expressions. Whitespace is preserved.

Example flow

  1. Create a Flow with a POST Webhook trigger and protect the webhook.
  2. Add Send SMS (Alive5) with the operation key send_sms. Enter your API key and sender details, and set To number to {{$trigger.payload.phone}}.
  3. Set Message to Hello {{$trigger.payload.name}}, your request was received. Connect the resolve path to your next operation and the reject path to error handling.
  4. Trigger the webhook with a payload containing phone and name. Read {{send_sms.messageId}} and {{send_sms.conversationId}} in later operations.

Check the result

Read {{send_sms.messageId}} and {{send_sms.conversationId}} in later operations. The conversation ID is empty if absent. Success confirms submission, not delivery.

Limits

HTTP failures and Alive5 response errors follow the reject path. The operation does not retry. Check conversation history before retrying a transport failure or unclear response to avoid duplicate texts.

Keep the API key out of the database

On self-hosted Directus 11, set these server environment variables and restart Directus:

Environment
ALIVE5_API_KEY=your-alive5-api-key
FLOWS_ENV_ALLOW_LIST=ALIVE5_API_KEY

Set the operation’s API key option to {{$env.ALIVE5_API_KEY}}. If other variables are already allowed, add ALIVE5_API_KEY to the comma-separated FLOWS_ENV_ALLOW_LIST. The operation stores the expression instead of the key.

API key storage

The masked input is a display setting. A directly entered key is stored in operation options and revisions. Restrict Flow access and rotate any key previously stored there; replacing it does not erase older revisions.
