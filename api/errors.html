Errors and responses

The HTTP status is not the source of truth. Check the envelope.

Check three fields

A call succeeded only when code is below 400 and error is empty. Some endpoints nest a second envelope inside data, so check that too.

is-ok.js 
function isOk(body) {
  const inner = body?.data ?? {};
  const code  = inner.code ?? body.code ?? 200;
  const err   = inner.error ?? body.error;
  const empty = err == null || (typeof err === "object" && Object.keys(err).length === 0);
  return code < 400 && empty;
}

Codes you will see

Code Meaning Action
200 Call accepted Confirm error is empty before trusting it
400 Missing or invalid field Fix the request; do not retry unchanged
401 No API key Add the header
404 No matching records Often an empty result, not a broken endpoint

Empty error objects

Several write endpoints return "error": {} alongside a 400 code, with no field name. When that happens, compare your request against the field list in the reference. a missing required field is the usual cause.

Empty 404s

Conversation and report endpoints return code 404 when the account has no matching records for the filter. Treat it as an empty list rather than an error, unless the same filter returned data before.
