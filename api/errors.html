Errors and responses

Check both the HTTP status and every response envelope.

Check three fields

A call is accepted only when the HTTP status and response code are successful and error is empty. Some endpoints nest a second envelope inside data, so check that too.

is-ok.js 
// Pass the HTTP response status: isOk(body, response.status).
function isOk(body, httpStatus) {
  if (!(httpStatus >= 200 && httpStatus < 300)) return false;
  if (!body || typeof body !== "object" || Array.isArray(body)) return false;
  if (body.code == null) return false;
  for (let part = body; part; ) {
    if (part.code != null && !(Number(part.code) >= 200 && Number(part.code) < 300)) return false;
    const error = part.error;
    const empty = error == null ||
      (typeof error === "object" && Object.keys(error).length === 0);
    if (!empty) return false;
    const next = part.data;
    part = next && typeof next === "object" && !Array.isArray(next) &&
      ("code" in next || "error" in next) ? next : null;
  }
  return true;
}

Codes you will see

Code Meaning Action
200 Call accepted Confirm error is empty before trusting it
400 Missing or invalid field Fix the request; do not retry unchanged
401 No API key Add the header
404 Not found Verify the endpoint, filters, and response body

Empty error objects

Several write endpoints return "error": {} alongside a 400 code, with no field name. When that happens, compare your request against the field list in the reference. Check required fields before attempting the request again.

Not-found responses

Check code and error in the response body. Verify the endpoint and requested resource before deciding how to handle a not-found response.
