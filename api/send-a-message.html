Send a message

Two calls: look up the channel and user, then send.

Use your own Alive5 account. Set ALIVE5_FROM_NUMBER to an SMS line on that account and RECIPIENT_NUMBER to a phone you control. Use E.164 format, including the country code.

1. Find your IDs

A send needs the channel that owns the business number and the user it is credited to. One call returns both.

GET /objects/channels-and-users/list 
curl https://api-v2.alive5.com/public/1.0/objects/channels-and-users/list \
  -H "X-A5-APIKEY: $ALIVE5_KEY"

Channels whose channel_label is a phone number are SMS lines. Take its channel_id, and a user_id from that channel's agents array. Save these as CHANNEL_ID and USER_ID.

2. Send the SMS

This SMS endpoint uses api.alive5.com; the directory call above uses api-v2.alive5.com. Send the fields as multipart form data. 

curl https://api.alive5.com/public/1.0/conversations/sms/send \
  -H "X-A5-APIKEY: $ALIVE5_KEY" \
  -F "phone_number_from=$ALIVE5_FROM_NUMBER" \
  -F "phone_number_to=$RECIPIENT_NUMBER" \
  -F "message=Hello from Alive5." \
  -F "channel_id=$CHANNEL_ID" \
  -F "user_id=$USER_ID"
const form = new FormData();
form.set("phone_number_from", process.env.ALIVE5_FROM_NUMBER);
form.set("phone_number_to", process.env.RECIPIENT_NUMBER);
form.set("message", "Hello from Alive5.");
form.set("channel_id", process.env.CHANNEL_ID);
form.set("user_id", process.env.USER_ID);

await fetch("https://api.alive5.com/public/1.0/conversations/sms/send", {
  method: "POST",
  headers: { "X-A5-APIKEY": process.env.ALIVE5_KEY },
  body: form
});

Fields

Field Type Notes
phone_number_from string An Alive5 business line, E.164 format
phone_number_to string Recipient mobile number, including country code
message string Up to 1,600 characters; longer texts split into segments
channel_id uuid Inbox the thread belongs to
user_id uuid Teammate credited with the send
This sends a real text. Test against a number you control. Attachments are not supported on this endpoint.

Check API acceptance

The response returns a message ID, a status, and the thread ID. The same thread is what your team sees in the shared inbox, so a reply continues the conversation rather than opening a new one.

Example response 
{
  "code": 200,
  "data": {
    "data": {
      "message_id": "example_message",
      "message_status": "queued",
      "thread_id": "example_thread",
      "From": "+12025550100",
      "To": "+12025550123",
      "direction": "outbound",
      "message_content": "Hello from Alive5."
    }
  },
  "error": {}
}

API acceptance does not confirm carrier delivery.
